# GF(2^16): `Gf16`

Public API timings for the AES-rooted quadratic tower field and the native
GF(2^16) field-kernel competitor panel. Every result cell reports Tiger Lake /
Golden Cove; shared hosts, toolchain, sampling, and number format:
[BENCHMARKS.md](../BENCHMARKS.md). Same-session v2-versus-v3 numbers live in
the [v2 comparison](v2/gf16.md).

## Setup

| Setting | Value |
| --- | --- |
| Campaign | `just bench-gf-comp` for self-timings; `just bench-gf16-comp` for competitors |
| Resolved backend | `v4x` / `v3_gfni_crypto`; Tiger Lake gather retains its GFNI path |
| Competitors | GF-Complete 1.03 at `a6862d10c9db467148f20eef2c6445ac9afd94d8`; `reed-solomon-erasure` 6.0.0; `reed-solomon-simd` 3.1.0; Leopard-RS 1.x (pre-Leopard2) at `6e5725ebdf9da4370b0bcc4f70fa8eb66f4e6198` |
| Competitor build | `external/gf16-bench` with `fgf/simd512`; GCC and G++; GF-Complete with SSSE3, SSE4, and PCLMUL; Leopard-RS with AVX2; no OpenMP workers |
| Competitor backends | GF-Complete: verified SSSE3 split-4/16 region; `reed-solomon-erasure`: scalar GF16; `reed-solomon-simd`: explicit AVX2 engine; Leopard-RS 1.x: verified AVX2 |
| Representations | `fgf`: AES quadratic tower, adjacent component bytes. GF-Complete: polynomial `0x1100b`, little-endian words. `reed-solomon-erasure`: its `0x11D` quadratic extension, big-endian components. `reed-solomon-simd` and Leopard-RS: Cantor coordinates, low and high planes within each tile. |
| Validation | Independent scalar multiplication, bijective field maps, and every basis product; all-field regions, zero, unit, and full-field coefficients, repeated calls, legal tile boundaries, and offset alignment; every timed geometry and coefficient schedule |
| Competitor sampling | Five runs per host; median of per-run medians. Each cycle covers every arm permutation, and an untimed batch of the same arm precedes every timed batch. Samples average 32 calls below 64 KiB, 8 below 1 MiB, and 1 otherwise. |
| Competitor stopping | At least three complete permutation cycles; target budget 500 ms including warm batches; cap 1200 samples per arm |
| Fixtures | Page-aligned native buffers; matched field elements and coefficients; one fixed coefficient set, or cycling through sixteen prepared sets |
| Throughput | Self-timings follow the shared convention. Competitor cells count source bytes per operation for every arm, including accumulating multi-row operations. |

- Field isomorphisms map sources, destination initial values, and coefficients before timing. Native representations are not wire-compatible.
- Setup, allocation, input generation, conversion, coefficient logarithms, and reusable preparation are excluded. GF-Complete's per-call coefficient table construction remains included.
- `fgf` uses its public single-row operations and prepared gather and matrix operations. Multi-row competitor arms compose their native overwrite and accumulating region primitives; they do not encode a codec's generator matrix.
- `reed-solomon-simd` exposes matched in-place scaling through `Engine::mul` only. `reed-solomon-erasure` and the Leopard-RS 1.x bridge supply no matched native in-place region primitive.
- The Leopard-RS 1.x overwrite calls upstream `mul_mem`; accumulation uses upstream `LEO_MULADD_256` with benchmark-only buffer load and store glue. Leopard2 exposes codec operations but no public field-region primitive, so it has no matched arm.
- Timed coefficients are nonzero, nonunit full-field elements. Zero and unit cases validate adapters but contribute no timing rows.
- Small rows include public-call and harness overhead. Large-row control and sample variability remain unresolved; differences comparable to the controls or run variability are not qualified comparisons.
- Competitor multi-row cells count source bytes, not source bytes × destinations, so they use a different numerator from the self-timing tables.
- Checked bridge and call-boundary overhead are included. Output read-back, data transfer, and codec costs are not timed.
- GF-Complete uses `gf_init_easy` with its default polynomial and region configuration; alternative GF-Complete configurations are not swept.
- GF-Complete and Leopard-RS use BSD-style licenses; the Rust competitors use MIT, or MIT with BSD-3-Clause notices.
